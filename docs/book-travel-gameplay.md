# 穿书玩法

本文记录 MuseAI 里「穿书」在产品上具体指什么、玩家怎么玩、和聊天/冒险差在哪。对应实现已落地，不是草案。

记忆整理（摘要、关键选择、未决冲突、偏离）见 [book-travel-memory-keeper.md](./book-travel-memory-keeper.md)。

## 一句话

穿书是：**带着一本已整理好的小说，选一个入场点和身份，进入原书世界里改写剧情。**

代码里叫 book travel。侧栏「素材」是装配世界，「穿书」是进去玩。路由分别是 `/book-travel-materials` 和 `/story`。

它不是伴侣聊天，也不是开放跑团。核心乐趣是「我穿进去了，选择会不会偏离原著」。

## 和另外两个互动模式的差别

| | 聊天 | 冒险 | 穿书 |
| --- | --- | --- | --- |
| 入口 | `/chat` | `/adventure` | `/story`（先装配 `/book-travel-materials`） |
| 你是谁 | 和一张角色卡一对一 | 冒险主角，AI 当 DM | 入场导演给出的可扮演身份 |
| 绑定什么 | 一本世界书 + 一张角色卡 | 一本世界书 + 多张角色卡 | 大纲 + 世界书 + 角色卡，先装配成世界模型 |
| 剧情从哪来 | 角色扮演对话 | DM 旁白 + 即兴推进，**无原书锚点** | 贴着原大纲/世界模型，**允许偏离并记录** |
| 每回合 | 一轮对话 | DM 旁白 + 可选角色台词工具 | 分类：继续本场，或换场；每次只写 1 个节拍 |
| 记忆 | 上下文压缩；手动封存写回角色卡 | 同左 | 穿书自己的剧情账本，不写回角色卡 |
| 手机局域网 | 有 | 有 | **没有**，局域网页只有聊天 / 冒险 / 羁绊 |

设定可以复用：同一本世界书、同一张角色卡，可以拿去聊天、冒险、穿书。穿书额外强依赖**大纲**，因为要有原时间线和可偏离的正史。

## 冒险与穿书：基本差异

两者表面很像：都是你当主角、自由输入【说话】【行为】【剧情推进】、AI 不替你做决定。差别在**有没有「原著」要对齐**，以及**引擎怎么管剧情**。

### 一句话对照

| | 冒险 | 穿书 |
| --- | --- | --- |
| 定位 | 在设定世界里**自由跑团** | 在**已有小说骨架**里**改线并跟踪偏离** |
| 剧情锚点 | 只有世界书 + 角色卡，**没有原书时间线** | 大纲 + 装配出的世界模型（时间线、可能结局、隐藏信息边界） |
| 对偏离的态度 | 无「偏离原著」概念，往哪走都行 | **允许改线**；系统记录偏离，不是锁死正史 |

### 体验上差在哪

**冒险（`/adventure`）**

- AI 当 **DM**：回复里是 **DM 旁白**（环境、动作、氛围的第三人称叙述）+ NPC 对话；可选「动态加载」时，角色台词走 `role_play` 工具，避免串味。
- 走通用 **Agent 聊天循环**（`start_chat_completion_stream`）：一段段往下聊，上下文长了就**压缩摘要**。
- 剧情**当场即兴**，只要不离世界设定，不必对齐某条原书主线。
- 结束后可**手动封存记忆**，写回角色卡（关系、关键事件），进羁绊页。

**穿书（`/story`）**

- 不走 Agent 循环，而是 **分类 → 规划 → 写作** 流水线；每次只写 **1 个节拍**，换场才换场景。
- 必须先 **装配素材**（大纲 + 世界书 + 角色卡），选 **入场点** 和 **可扮演身份**。
- 规划师每轮看 `divergence`、`storyProgress`；记忆整理员维护 **剧情账本**（摘要、关键选择、未决冲突、相对原大纲的偏离）。
- 结局时给出 **世界线名、偏离度（0–100）、与原大纲对比**——偏离是玩法的一部分，不是 bug。
- 经历**不写回**角色卡；进度存 `book-travel-store` 快照。

### 常见误解

- **「穿书 = 不能偏离」** — 不对。可以改关键节点；系统要的是「改到哪了、还有哪些线没收、离原大纲多远」，避免长线玩丢正史约束。
- **「冒险 = 穿书但更自由」** — 大体对，但不只是「约束松一点」。冒险没有大纲/装配/换场/偏离度，**后端是另一套流水线**；穿书多出来的是**正史锚点 + 结构化状态**，不是简单多加几条提示词。

### 怎么选

- 想在同一世界观里**原创剧情、跑团式推进** → **冒险**
- 想**进入某本已整理的小说**、从某一幕入场、看选择会把世界线带偏多远 → **穿书**
- 想和**一个角色**长期对话、沉淀关系 → **聊天**（和上面两种都不是一类事）

### DM 旁白（仅冒险侧栏）

**DM** = 主持人（跑团里的 GM），**旁白** = 第三人称场面叙述（「雨敲窗棂，她退后半步……」），区别于 NPC 开口和你自己的【说话】。穿书没有单独叫 DM，但**写手写的 beat 正文**里同样包含叙述与对话，只是必须服从场景规划和原书约束。

## 玩家流程

```
整理素材 → 装配世界 → 选入场点与身份 → 每回合行动 → 存档或结局
```

### 1. 整理素材

穿书不从空白世界开局。至少需要：

- **大纲**：原书情节骨架（作品页或大纲页，也可反向大纲从长文提炼）
- **世界书**：时代、规则、地点、核心矛盾
- **角色卡**：进场会碰到的人

装配师被要求只归纳、不改写这些原文。隐藏信息边界会单独列出，避免模型把读者不该知道的正史剧透进可玩层。

### 2. 装配世界（素材页）

选中大纲、世界书、角色卡后，两步生成：

1. **装配师**产出 `assembledWorldModel`（时间线、冲突、可能结局、规则、地点、势力、角色画像、关系暗线、隐藏信息边界），以及初始 `stableMemory` / `volatileMemory`。
2. **入场导演**给出 3–6 个入场点、3–5 个可扮演身份。入场点里必须至少有一个是小说开场，允许从第一章进去。

装配结果可保存为素材预设，之后在穿书页直接选用。

### 3. 入场（穿书页）

选好预设、入场点、身份后点「开始穿书」。规划师写第一场的时间、地点、局势、在场人物；写手只写这场的入口节拍。之后 HUD 显示旅程状态：身份、目标、当前场景、线索/人物/世界动态、摘要。

开场第一场写完**不会**跑记忆整理；账本从第一次换场开始积累。

### 4. 每回合怎么玩

输入是自由文本，不是点预设选项。发送前选一种意图：

| 模式 | 前缀 | 含义 |
| --- | --- | --- |
| 说话 | 【说话】 | 你扮演的角色开口 |
| 行为 | 【行为】 | 你做出的动作或试探 |
| 剧情推进 | 【剧情推进】 | 你用旁白口吻指定后续走向或世界巧合 |

分类器只输出两种结果：

- `insert-beat`：还在当前场景里（对话、观察、小动作）。写手在本场追加 1 个节拍，可补丁易变记忆。
- `change-scene`：换地点、跳时间、重大决定。规划师先出新场景和新局势，写手再写入口节拍；换场成功后异步跑记忆整理。

硬约束：

- 不替用户角色说话、做决定、动手。
- 写手每次只写 **1 个 beat**，不预写下一步——下一步由玩家再输入。
- 写手不能改稳定记忆；时间、地点以规划师字段为准，不塞进 `stateChanges`。
- 每段叙事末尾给 3 个候选走向，玩家仍可无视它们自己打字。

### 5. 存档与结局

- **保存进度**：整局快照（世界模型、场景节拍、当前状态、剧情账本）写入本地 `book-travel-store`。可新建或覆盖。
- **重开**：清空当前局，回到选素材。
- **结局**：规划师给出的 `endingStatus` 不是 `none` / `active` 时，结局裁判总结最终结局、关键选择、与原大纲对比、各角色下场、世界线名和偏离度（0–100）。结束后输入框收起。

## 局中看到什么

- 场景标题、时间、地点、当前局势、场景目标
- 节拍正文（对话和旁白都写在 beat 里）
- HUD：扮演身份、目标、未决冲突、关键选择、偏离、线索与人物动态、最近 3 个回合
- 文风预设只在开场前可选；开始后入口会藏起来，避免中途改口吻把世界写崩

## 明确不做的事

- 不把穿书经历自动写回角色卡 / 羁绊档案
- 局域手机端不提供穿书
- 同场插节拍不跑记忆整理
- 没有 NPC 关系图，也没有「谁得到/失去什么」的利益账本
